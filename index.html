Algorithms Behind the Scheduler

Practical applications of classical algorithm paradigms engineered specifically for hospital and diagnostic suite constraints.

01 Fast Primary Engine

GREEDY

Priority Queue + Earliest Feasible Gap

Fast selection of feasible appointment slots based on priority and availability. Processes requests in Max-Heap order and greedily binds the earliest gap satisfying room, duration, and doctor constraints.

Priority Queue (Max-Heap)
↓ Highest Priority Request
↓ Find Earliest Feasible Gap
✓ Confirm Slot
02 Partition Engine

DIVIDE & CONQUER

Departmental Isolation & Merge

Break large scheduling problems into smaller groups such as departments, dates, or test types. Solves each sub-problem independently in parallel and merges into a conflict-free master timetable.

Full Hospital Request Pool
→ MRI / CT / Ultrasound / X-Ray
→ Solve Local Partitions
✓ Merge Master Timeline
03 Value Maximizer

DYNAMIC PROGRAMMING

State Matrix / Weighted Knapsack

Explore scheduling states to maximize successful appointments under constraints. Uses subproblem memoization to pick the optimal subset of appointments maximizing cumulative priority score.

State: DP[i, t]
max(DP[i-1,t], DP[i-1,t-w] + v)
2D State Table Memoization
✓ Optimal Clinical Value
04 Conflict Resolver

BACKTRACKING

Recursive Undo & Branch Probing

Try a scheduling choice, detect conflicts, undo the choice, and explore another possibility. Essential when initial assignments block downstream doctor consultations or urgent arrivals.

TRY Slot 10:00 AM
→ CONFLICT Detected (Occupied)
→ BACKTRACK (Undo 10:00 AM)
✓ TRY 10:45 AM → SUCCESS
05 State-Space Pruning

BRANCH & BOUND

Upper/Lower Bounding & Cutoff

Explore candidate schedules while pruning branches that cannot provide useful solutions. Computes an admissible bound and terminates branches that violate physical room exclusivity.

Candidate Schedules A, B, C, D
→ Bound(B) < Best Known (Prune)
→ Infeasible Overlap C (Prune)
✓ Selected Optimal: Branch A
06 Network Matching

GRAPH THEORY

Multi-Partite Flow Network

Represent relationships between patients, tests, doctors, rooms, and time slots. Models resource compatibility as edges and solves scheduling via maximum bipartite matching.

Patient → Test Compatibility
→ Test → Diagnostic Room
→ Room → Time Slot Window
✓ Doctor Supervision Edge

Core Data Structures Employed

  • Priority Queue (Max-Heap): O(1) peek, O(log N) insertion for sorting urgent patients by SLA weight.
  • Hash Maps & Sets: O(1) constant time room occupancy lookup and doctor availability sets.
  • Dynamic Programming Table: 2D array matrix tracking subproblem states DP[i][t].
  • State-Space Search Tree: Candidate branch representation with bounding functions for Branch & Bound.
  • Multi-Partite Graph: Adjacency lists linking Patients, Tests, Rooms, Slots, and Doctors.

Accurate Algorithm Complexity

  • Greedy Scheduler: O(N log N + N · S) time, O(N + S) space.
  • Divide & Conquer: O(K · (N/K log(N/K)) + N) time, O(N) space.
  • Dynamic Programming: O(N · W) time, O(N · W) space (W = discretized intervals).
  • Backtracking: O(M^D) with early state pruning, O(D) recursion stack.
  • Branch & Bound: Sub-exponential with tight admissible bounding.
  • Graph Network: O(V + E) BFS traversal / O(V² E) max flow matching.
